# Plugin: UploadThing

## Purpose
Handle file uploads to cloud storage without managing S3 buckets, presigned URLs, or multipart upload logic. UploadThing wraps all of that and exposes a typed API for defining upload routes, enforcing file constraints, and hooking into upload completion. Works well with Next.js and any React frontend.

## Server Route Configuration
Define upload routes in a single file — this is the source of truth for what files are allowed:

```ts
// app/api/uploadthing/core.ts
import { createUploadthing, type FileRouter } from 'uploadthing/next';
import { auth } from '@/lib/auth';

const f = createUploadthing();

export const ourFileRouter = {
  avatarUploader: f({ image: { maxFileSize: '2MB', maxFileCount: 1 } })
    .middleware(async ({ req }) => {
      const session = await auth(req);
      if (!session) throw new Error('Unauthorized');
      // Metadata returned here is passed to onUploadComplete
      return { userId: session.user.id };
    })
    .onUploadComplete(async ({ metadata, file }) => {
      // file.url is the permanent CDN URL
      await db.update(users).set({ avatarUrl: file.url }).where(eq(users.id, metadata.userId));
      // Return value is sent back to the client-side callback
      return { url: file.url };
    }),

  documentUploader: f({ pdf: { maxFileSize: '10MB' }, 'image/*': { maxFileSize: '5MB' } })
    .middleware(async ({ req }) => {
      const session = await auth(req);
      if (!session) throw new Error('Unauthorized');
      return { userId: session.user.id, orgId: session.user.orgId };
    })
    .onUploadComplete(async ({ metadata, file }) => {
      await db.insert(documents).values({ userId: metadata.userId, url: file.url, name: file.name });
    }),
} satisfies FileRouter;

export type OurFileRouter = typeof ourFileRouter;
```

Mount this router at `/api/uploadthing` with the provided route handler.

## File Type and Size Limits
Specify constraints per MIME type or category. The `f()` config object keys are MIME types or UploadThing shorthand (`image`, `video`, `audio`, `pdf`, `text`, `blob`):

```ts
f({
  'image/png': { maxFileSize: '4MB', maxFileCount: 5 },
  'application/pdf': { maxFileSize: '16MB', maxFileCount: 1 },
})
```

Files violating these constraints are rejected before upload begins — the client gets an error without uploading anything.

## Client-Side Hook
```tsx
import { useUploadThing } from '@/lib/uploadthing'; // generated by createNextRouteHandler

function AvatarUpload() {
  const { startUpload, isUploading, permittedFileInfo } = useUploadThing('avatarUploader', {
    onClientUploadComplete: (res) => {
      // res[0].serverData is what onUploadComplete returned
      toast.success('Uploaded!');
    },
    onUploadError: (error) => {
      toast.error(error.message);
    },
    onUploadProgress: (p) => setProgress(p),
  });

  return (
    <input
      type="file"
      accept={generateClientDropzoneAccept(permittedFileInfo?.config)}
      onChange={e => e.target.files && startUpload(Array.from(e.target.files))}
    />
  );
}
```

Use `permittedFileInfo` to derive `accept` strings — it reflects exactly what the server allows, keeping client and server in sync.

## `onUploadComplete` Callback — Access Control Enforcement
The `metadata` object is the only place to associate an upload with a user. The `middleware` runs server-side before the upload is authorized — use it to authenticate and attach user context. The file URL is public once uploaded; access control must happen at the application layer (check ownership in DB before serving).

Do not pass access tokens or sensitive data through the client-side `input` field — it goes through UploadThing's servers and cannot be trusted. Only use `middleware` for auth.

## Gotchas
- **File URLs are permanent CDN URLs** — they don't expire. If you need private files, don't use UploadThing's default CDN; use their private storage option or proxy through your own handler.
- **`onUploadComplete` can run in a serverless context** — if your DB call inside it fails, the file is uploaded but the DB record isn't written. Add a reconciliation job or use a transactional outbox if this matters.
- **The `useUploadThing` hook must be generated** — run `npx uploadthing generate` or use the provided `generateComponents()` helper to get typed hooks specific to your router.
- Dropzone integration: pass `onDrop` to `startUpload` — files from `react-dropzone` are `File[]`, same as `HTMLInputElement.files`.

## Key Rules
- **Authenticate in `middleware`, not in `onUploadComplete`** — the middleware is the gate; by the time `onUploadComplete` runs, the upload has happened
- **Use `metadata` to carry user context** — never trust data the client sends with the file
- **Use `permittedFileInfo` to derive `accept` strings** — keeps client and server constraints in sync
- **CDN URLs are public and permanent** — if you need private files, proxy them or use private storage
- **Handle `onUploadComplete` failures** — a failed DB write after a successful upload leaves orphaned files
