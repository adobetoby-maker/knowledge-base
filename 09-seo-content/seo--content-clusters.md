# SEO: Content Cluster Strategy

## Overview
Google rewards topical authority — demonstrating comprehensive expertise on a subject, not just optimizing individual pages for individual keywords. Content clusters signal expertise by covering a topic from every angle within a coherent internal link structure. The result: the entire cluster lifts, not just the pillar page, because internal links pass authority across the group.

## Architecture

**Pillar page**
- Comprehensive overview of the main topic (2000–4000 words)
- Targets a high-volume head term ("project management software")
- Covers all major subtopics at a surface level (each subtopic → a cluster page)
- Links out to every cluster page using descriptive anchor text
- Intentionally does not fully exhaust any subtopic — leaves depth to clusters

**Cluster pages**
- Each covers one specific subtopic in depth (800–1500 words)
- Targets long-tail variant of the head term ("project management software for remote teams")
- Links back to the pillar page (always)
- Links to 2–3 related cluster pages in the same cluster (not just the pillar)
- Does not duplicate the pillar — adds depth the pillar summary omitted

**Internal link structure**
- Pillar → all clusters (hub-and-spoke)
- Clusters → pillar (always)
- Clusters → related clusters (reinforces semantic field)
- Anchor text: descriptive, keyword-relevant — not "click here" or "read more"

## Why It Works

Search engines build a topical graph of your site. Pages that are tightly linked with consistent semantic signals are understood to be about the same topic. A strong cluster sends the signal: "This site has comprehensive, interconnected coverage of [topic]." This outperforms publishing 12 independent pages on loosely related subjects because the link signals are isolated and the topical coherence is missing.

## Cluster Size

- Minimum viable: 1 pillar + 4 clusters (signal starts forming)
- Sweet spot: 1 pillar + 8–12 clusters (full topical coverage)
- Maximum useful: as many subtopics as have genuine search demand
- Do not create cluster pages for subtopics with no search volume — thin content risk

## Building a Cluster

1. Choose the head term that defines the pillar
2. Identify all questions users ask about this topic (AnswerThePublic, SERP "People Also Ask")
3. Group questions into subtopics — each group becomes one cluster page
4. Audit existing content: some pages may already cover subtopics and just need to be linked properly
5. Write the pillar last (or rewrite an existing page) — reference every cluster in it
6. Publish clusters first, then publish/update pillar with links to all of them

## Key Rules

- One pillar per cluster — two pillar pages competing for the same head term splits signals
- Every cluster page must have unique value — not just a thin variant of the pillar
- Internal link anchor text must use the target keyword of the destination page
- Update the pillar whenever a new cluster page is added
- Measure: track rankings for the pillar head term and cluster long-tails separately in GSC
- Clusters can belong to only one cluster (dual membership creates topical confusion)
