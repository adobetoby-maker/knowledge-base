# Skill: GraphQL Code-First Setup

## Overview
GraphQL gives clients precise data fetching and eliminates over/under-fetching, but naive implementations have N+1 query problems, expose internals through introspection, and allow clients to DOS the server with deeply nested queries. Code-first schema generation (vs SDL-first) keeps types in sync with your business logic and catches schema errors at compile time.

## Implementation

### 1. Setup with Pothos (code-first)
```ts
// lib/graphql/schema.ts
import SchemaBuilder from '@pothos/core';
import PrismaPlugin from '@pothos/plugin-prisma';
import { db } from '../db';

const builder = new SchemaBuilder<{
  Context: { userId: string; db: typeof db };
  PrismaTypes: PrismaTypes;    // generated by pothos-prisma
}>({
  plugins: [PrismaPlugin],
  prisma: { client: db },
});

// Define types
const UserType = builder.prismaObject('User', {
  fields: (t) => ({
    id: t.exposeID('id'),
    name: t.exposeString('name'),
    email: t.exposeString('email'),
    // Omit sensitive fields — passwordHash is never exposed
    posts: t.relation('posts'),
  }),
});

// Query root
builder.queryType({
  fields: (t) => ({
    me: t.prismaField({
      type: 'User',
      resolve: (query, _root, _args, ctx) =>
        db.user.findUniqueOrThrow({ ...query, where: { id: ctx.userId } }),
    }),
    user: t.prismaField({
      type: 'User',
      args: { id: t.arg.id({ required: true }) },
      resolve: (query, _root, { id }, ctx) => {
        // Authorization: only admins can fetch arbitrary users
        if (!ctx.isAdmin) throw new Error('Forbidden');
        return db.user.findUniqueOrThrow({ ...query, where: { id } });
      },
    }),
  }),
});

export const schema = builder.toSchema();
```

### 2. DataLoader for N+1 prevention
```ts
// lib/graphql/loaders.ts
import DataLoader from 'dataloader';

export function createLoaders() {
  return {
    // Batch: instead of 1 query per post author, runs 1 query for all
    userById: new DataLoader<string, User>(async (ids) => {
      const users = await db.user.findMany({ where: { id: { in: [...ids] } } });
      const map = new Map(users.map(u => [u.id, u]));
      return ids.map(id => map.get(id) ?? new Error(`User ${id} not found`));
    }),
  };
}

// In context factory
const context = {
  userId: req.auth.userId,
  db,
  loaders: createLoaders(),  // fresh per request (no cross-request cache pollution)
};
```

### 3. Query depth and complexity limits
```ts
import { createComplexityPlugin } from 'graphql-query-complexity';
import depthLimit from 'graphql-depth-limit';

const server = createYoga({
  schema,
  context,
  plugins: [
    // Block deeply nested queries (e.g., friends.friends.friends...)
    useValidationRule(depthLimit(10)),
    
    // Block expensive queries before execution
    createComplexityPlugin({
      maximumComplexity: 1000,
      estimators: [
        fieldExtensionsEstimator(),
        simpleEstimator({ defaultComplexity: 1 }),
      ],
      onComplete: (complexity) => {
        console.log(`Query complexity: ${complexity}`);
      },
    }),
  ],
});
```

### 4. Persisted queries (production)
```ts
// Clients send query hash instead of full query text
// Prevents arbitrary queries from reaching prod
const persistedQueriesPlugin = usePersistedOperations({
  getPersistedOperation: async (key: string) => {
    // Look up pre-approved query by hash
    return queryStore.get(key) ?? null;
  },
  allowArbitraryOperations: process.env.NODE_ENV !== 'production',
});
```

### 5. Disable introspection in production
```ts
import { NoSchemaIntrospectionCustomRule } from 'graphql';

const server = createYoga({
  schema,
  validationRules: process.env.NODE_ENV === 'production'
    ? [NoSchemaIntrospectionCustomRule]  // hides schema from attackers
    : [],
});
```

## Key Rules
- **Use DataLoader for every relation resolver** — without batching, fetching a list of 100 posts triggers 100 user queries (N+1).
- **Create loaders fresh per request** — DataLoader caches within a request scope; sharing across requests serves stale or wrong-user data.
- **Set depth and complexity limits before launching** — without them, a single malicious query can crash the server.
- Never expose sensitive fields (passwords, tokens, internal IDs) — omit from schema definition entirely.
- **Disable introspection in prod** — introspection reveals your entire data model to anyone who can query the endpoint.
- Use persisted queries in production to prevent query injection and enable exact cost analysis.
- Resolver authorization logic belongs in the resolver, not a middleware — middleware can't access resolver-specific context.
