# NEEDS_HUMAN Pattern — Overnight Blocker Handling

**When:** Running autonomous overnight sessions. The model encounters something it can't resolve safely without a human decision.
**Rule:** Never stop the session and never take an unsafe action. Log the blocker and continue with other tasks.

## The Pattern
When blocked, write to `NEEDS_HUMAN.md` in the project root and continue:
```bash
cat >> /Users/drive/[project]/NEEDS_HUMAN.md << 'EOF'

## [timestamp] — [task name]
BLOCKED: [what you were trying to do]
REASON: [why you're blocked]
OPTIONS:
  A) [option A and its tradeoff]
  B) [option B and its tradeoff]
NEXT STEP AFTER REVIEW: [what to run once human decides]
EOF
```

## What Triggers NEEDS_HUMAN

### Unsafe Operations
```
- Would need to run: rm, DELETE, DROP, TRUNCATE
- Would need to push to main/master
- Would need to apply a migration with destructive changes
- Would need to use git reset --hard or force push
```

### Ambiguous Requirements
```
- Task says "update the UI" but two valid interpretations exist
- Configuration choices that affect production behavior
- Conflicting instructions in different files
```

### Missing Prerequisites
```
- Environment variable not set (and can't proceed without it)
- Dependency not installed and unsure of correct version
- External service needs credentials not available
- Target file doesn't exist (maybe wrong path in task)
```

### Build Failures After Changes
```
- Made changes, npm run build fails
- TypeScript errors in a file not directly modified (indicates a wider issue)
- Tests failing that were passing before this task
```

## NEEDS_HUMAN.md Format
```markdown
# NEEDS_HUMAN

Generated by overnight batch session on [date]
Review and resolve before next session.

## [2026-05-18 02:34] — Add user avatar upload
BLOCKED: Supabase Storage bucket 'avatars' doesn't exist.
REASON: Cannot create bucket without knowing public vs private policy.
OPTIONS:
  A) Create as PUBLIC — avatars load fast without auth, but all URLs are guessable
  B) Create as PRIVATE — requires signed URL on every image load
NEXT STEP AFTER REVIEW: 
  Run in SQL editor: INSERT INTO storage.buckets (id, name, public) VALUES ('avatars', 'avatars', [true/false]);
  Then re-run overnight task: "Implement avatar upload for user profile"

## [2026-05-18 03:15] — Update pricing table
BLOCKED: Current pricing in lib/pricing.ts differs from task spec.
  Task says: "Standard plan $49/mo"
  Code says: "Standard plan $39/mo"
REASON: Unsure if this is a price change or a typo in the task spec.
OPTIONS:
  A) Update to $49 as specified
  B) Keep $39 (maybe task spec is outdated)
NEXT STEP AFTER REVIEW: Confirm correct price, then update lib/pricing.ts line 23.
```

## Continue Running After Blocking
The whole point is non-interruption. After writing to NEEDS_HUMAN.md, the session should:
1. Mark the blocked task as "blocked" in the session log
2. Move to the next task in the list
3. At session close, summarize how many tasks blocked vs completed

## Morning Review Process
When you return:
1. Read NEEDS_HUMAN.md first
2. Resolve each item (make the decision)
3. Re-run the blocked tasks with the decision explicit in the prompt
4. Delete the resolved items from NEEDS_HUMAN.md
