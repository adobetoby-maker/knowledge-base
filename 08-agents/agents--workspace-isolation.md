# Agent Workspace Isolation

## Why Isolation Is Non-Negotiable

Agents that write files or execute code are dangerous when multiple runs share a workspace. Run A's partial output becomes Run B's input. A failed run leaves garbage that corrupts the next run's reads. An agent that modifies shared paths can interfere with the production filesystem or other agents running in parallel.

Isolation ensures: each run starts clean, failures don't pollute future runs, and concurrent agents can't interfere with each other.

## Temp Directory Per Run

Every agent run gets its own isolated directory, created at task start and owned exclusively by that run:

```typescript
import { mkdtempSync } from "fs";
import { tmpdir } from "os";
import { join } from "path";

function createAgentWorkspace(taskId: string): string {
  const dir = mkdtempSync(join(tmpdir(), `agent-${taskId}-`));
  return dir; // e.g., /tmp/agent-task_abc123-xK4p9q/
}
```

Pass this path into the agent's context. Every file operation the agent performs goes through this root. The agent should never receive an absolute path that points outside its workspace.

Why `mkdtemp` and not a predictable path like `/tmp/agent-{taskId}`? Predictable paths are a security risk — an attacker who knows the format could pre-create the directory with malicious content. Random suffixes prevent this.

## Cleanup on Completion and Failure

The workspace must be cleaned up regardless of how the run ends. Use a try/finally pattern:

```typescript
const workspace = createAgentWorkspace(task.id);
try {
  await runAgent(task, workspace);
  await archiveOutputs(workspace, task.id); // save what matters before cleanup
} finally {
  await rm(workspace, { recursive: true, force: true });
}
```

Archive outputs before cleanup. Copy the files that matter to permanent storage (S3, database, etc.) while the workspace still exists. Then delete the entire workspace directory tree.

Don't skip cleanup on failure. Accumulated failed run directories fill disk, and their partial outputs are a debugging trap — future developers or agents may mistakenly read stale data.

## File Permission Scoping

The process running the agent should not have write access to paths outside the intended workspace:

- Run agent processes as a non-root user with a restricted umask
- Use a dedicated service account that owns only the temp directory tree
- Never grant agents access to `/etc`, `/home`, or application config paths
- If using containers: mount the workspace as the only writable volume

For agents that generate code and execute it: use a separate sandboxed process (subprocess, container, or VM) to run agent-generated code. Never execute agent output in the same process that has filesystem access.

## Shared Paths Agents Must Not Write To

These paths are off-limits for agent writes under all circumstances:

- Project source directories (`/Users/drive/*`, `~/projects/*`) — unless the task is explicitly a code modification task with human review gating
- Database files or connection sockets
- Other agents' workspace directories
- Log aggregation paths that tools read from
- Environment variable files (`.env`, `.env.local`)

If an agent task legitimately needs to modify a source file, use a branch + PR workflow: clone to workspace, modify, push branch, open PR. The agent never writes directly to the main working tree.

## Detecting Workspace Escape

Add a path guard to every file operation the agent can invoke:

```typescript
function assertInWorkspace(filePath: string, workspace: string) {
  const resolved = resolve(filePath);
  if (!resolved.startsWith(resolve(workspace) + "/")) {
    throw new Error(`Path escape attempt: ${filePath} is outside workspace ${workspace}`);
  }
}
```

Log and alert on escape attempts. A legitimate agent task should never need to escape its workspace. If it's trying to, that's either a prompt injection attack or a logic bug — both warrant investigation.

## Key Rules

- Every agent run gets a unique temp directory created with `mkdtemp` (not a predictable path)
- Clean up the workspace in a `finally` block — always, including on failure
- Archive outputs to permanent storage before cleanup, not after
- Agent process permissions must be scoped to the workspace — no write access to shared paths
- Guard all file operations with a path-containment check and throw on escape
- Code generated by agents must execute in a separate sandbox, not the agent's own process
